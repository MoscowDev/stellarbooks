# StellarBooks Fixtures

This folder holds two kinds of data. They have different evidential value, so keep them apart.

## Real testnet capture

`data/testnet-ledger.json` is public testnet ledger **5796891**, captured on 2026-11-18 from
the Stellar testnet RPC.

- `decodeLedger` decodes all 25 transactions. `packages/stellar-ingest/test/ledger-decoder.test.ts`
  asserts exact values for a payment, account creation, account merge, a path payment to self, two
  failed transactions and a Soroban fee-bump.
- `decodeNativePayment` independently checks the same XLM payment and fee.

## Captured operation ledgers

`data/captured/` holds unmodified public testnet ledgers captured on 2026-11-25 with
`tools/fixture-gen` (`capture.js`), most on 2026-11-25. Each file names its target transaction. Exact assertions are
in `packages/stellar-ingest/test/captured.test.ts`.

| File                                        | Target transaction                                          |
| ------------------------------------------- | ----------------------------------------------------------- |
| `claimable_balance-5919620.json`            | Create (tx 1) and an unrelated claim (tx 7)                 |
| `clawback-5918543.json`                     | Clawback of an issued asset, text memo                      |
| `clawback_claimable_balance-5918066.json`   | Clawback of a claimable balance                             |
| `liquidity_pool_deposit-5918402.json`       | Pool deposit                                                |
| `muxed_payment-5917783.json`                | Issued-asset payment to a muxed address                     |
| `muxed_source_payment-5920622.json`         | XLM payment from a muxed transaction source                 |
| `path_payment_strict_receive-5919962.json`  | Strict-receive path payment to self                         |
| `path_payment_strict_send_to_other-5919253.json` | Strict-send path payment to another account            |
| `trustline_removal-5919140.json`            | Trustline removal                                           |

No `liquidity_pool_withdraw` appeared in the 3,000 ledgers scanned.

## Synthetic classifier cases (not golden fixtures)

`data/synthetic-cases.ts` contains ten hand-written cases. Each one is marked with
`provenance: 'synthetic'`.

| Property             | Synthetic cases                                                   |
| -------------------- | ----------------------------------------------------------------- |
| Ledgers and hashes   | Invented (ledger 100 onward, hashes such as `1111…`)              |
| Input format         | Normalized records written by hand, not decoded XDR              |
| Expected events      | Written by hand                                                   |
| Expected journal     | Generated by `mapEvents`, the function under test                 |
| What they prove      | The classifier routes normalized input to the expected event kind |
| What they don't prove | That StellarBooks matches real Stellar behavior                  |

The test compares only event counts, kinds and wallets, plus the number of journal entries.
Because the expected journal comes from the mapper, a mapping bug would not cause a failure.
Do not cite these cases as verification of an operation type.

The ten cases are shaped like: three payments, a strict-send path payment, an account merge, a
claimable-balance lock, a liquidity-pool deposit, a clawback, a failed transaction and a Soroban
contract transfer. They are not evidence of chain behaviour; real-ledger coverage is in the
captured ledgers above.

## Replacing them with real fixtures

Q-035 and [issue 20](../issues-backlog/20-independent-goldens.md) track the replacement. A real
golden fixture should:

1. Come from a captured testnet transaction (raw XDR committed, with ledger and capture date).
2. Have expected events and postings written and reviewed independently of the mapper.
3. Assert source keys, lines and amounts exactly, so a one-unit change fails the test.

`tools/fixture-gen` (`capture.js`) captures real ledgers from live testnet traffic without keys.
